# v3.34.0 —— 组件化全屏界面（Textual）· 运行环境自带离线 wheel

> 一句话：界面从"自己手搓全屏"升级到**组件化框架**，并且把**运行环境做成自带的**——
> 用户拿到仓库，`python setup_env.py --ensure` 离线也能把界面依赖装齐；不装也照旧能用核心。

## 为什么换引擎

社区那份《Claude Code 用户体验深潜》里被反复强调的一点是：**固定区 + 滚动区 + 组件化**。
手搓全屏（`ui/ace_fullscreen.py`）能做到，但每加一个交互（鼠标命中、增量搜索、和弦键位、
覆盖层冻结输入）都要自己补一层渲染与焦点管理，成本会越滚越高。

所以表现层换成 **Textual**，但守住三条边界：

| 边界 | 落地 |
| --- | --- |
| 核心零依赖 | `tui/` 是**可选包**：没装 Textual 时 `import tui` 不炸，`--tui` 如实回退 REPL |
| 引擎不分叉 | `--tui` 与 REPL 走**同一个 `_process_line`**，两套界面同一颗脑 |
| 纯逻辑先测 | 桥接 `tui/bridge.py` 不依赖 Textual，CI 里没框架也能测 |

## 四区骨架

```
┌ ACE · 模型 · 权限 ───────────────────────────── Header（常驻）
│  ❯ 你的输入                                     ← 转写区（可滚动）
│  ◈ 回答
│  ⚙ file_read ✓
├ 轮 2 · 工具 3 · 上下文 18% ──────────────────── Status（常驻单行）
│ ❯ 输入框                                        ← 输入栏（固定，草稿不丢）
└ Ctrl+O 展开 · Ctrl+T 任务树 · Ctrl+Q 退出 ───── Footer（读当前绑定）
```

- **输入栏与状态行 dock 在底部**：只有转写区滚动，目光不用满屏找东西
- **提交后焦点无条件回输入框**：打完字不会"字没进去"
- **清屏只清转写区**（`Ctrl+L`），状态行和输入栏不动

## 引擎↔界面：一根纯逻辑的管子

引擎在别的线程里 `print`，界面在主线程挂组件 —— 两个线程同时写屏幕会把界面打花。
`tui/bridge.py` 把这根管子抽出来，规矩只有三条，但每条都对应一个真实事故：

| 规矩 | 不这么做会怎样 |
| --- | --- |
| 带 `\r` 的写整条丢掉 | spinner 的原地重绘进滚动区 → 一屏残影 |
| 剥掉 ANSI | Textual 自管样式，留着颜色码会串进文本 |
| `isatty()` 恒 False | 引擎以为自己在终端里，又弹一套自己的交互框 |

半行**先留着**（`flush()` 时补上），最后一个字不会静默丢。

## 环境自带：`setup_env.py` + `vendor/`

- 多环境发现：`ACE_PYTHON` → `.ace_env` → 常见开发环境 → PATH `python`/`python3` → `py -3`
- **真的 `import` 一次**才认可用 —— Windows 商店占位解释器会在这一步被拦住
- **11 个 wheel 随仓库发布（约 3.1 MB）**，`--ensure` 先离线（`--no-index`）装，装不上再走在线索引
- `--vendor` 一条命令刷新 `vendor/`（维护者换版本时用）

```bash
python setup_env.py --check          # 看看现在这台机器有什么
python setup_env.py --ensure         # 一键备齐（离线优先）
python setup_env.py --print-python   # 给启动器问路用（ace.cmd 就吃这个）
python ai_code.py --tui              # 起组件化界面
```

## 兼容性

- 无破坏性变更；不装 Textual 一切照旧（核心零依赖）
- i18n 三语各 517 键对齐
- 新增测试段 `[60]`：桥接六条规矩 + Textual 无终端测试台（`run_test()` 真驱动输入→引擎→转写区）
  + `--tui` 接线源码级断言；**没装 Textual 的环境只跳过界面那几条，不判失败**

# v3.35.0 —— 防误触宽限期 · 工具看板（四态点 + 同帧同步）

> 对应交互规格缺口第 2、3 条：**误触不等于放行**，**工具要看得见四态**。

## 一、飞过来的回车，不算放行

真实的坑：模型还在跑，用户随手敲了个回车想"催一下"。就在这一刻授权对话框弹出来，
那个回车**落在了对话框上** —— 一次误触变成了一次放行。`input()` 的缓冲会把对话框
出现前敲的键原样喂给它，这不是理论风险。

```
对话框贴出            答案回来
   t0 ──────────────────── t1
        └─ < 200ms ─┘
        判为飞行按键：不采纳，重问一次
```

- 口径：`t1 - t0 < 200ms` → 丢弃。**人不可能读完一个三选一再作答**。
- 方向永远**收紧**：丢弃 = 按"没回答"处理，**不是**按"同意"。
- 重问上限 2 次：两次都判成飞行按键说明这不是误触（可能是自动化在喂输入），
  再拦就变成"用户明明答了却进不去"。
- `ACE_PERM_GRACE_MS` 可调，`0` = 关掉；**写坏/越界一律落回默认** ——
  配置错误不该把安全口径悄悄改成"不设防"；上限 5 秒（再长，这条保护自己就成了新问题）。
- 授权与计划审批**共用同一个入口**：两个危险对话框不会一个有一个没有。

## 二、工具看板：四个状态，一个钟

以前只有一行"正在调用工具"，用户看不出**这一步完了没**，也看不出**后面还排着几个**。

| 状态 | 点 | 含义 |
| --- | --- | --- |
| `queued` | `○` | 知道要做，还没轮到 |
| `running` | `▁▃▅▇▅▃` | 正在跑（一个字形循环） |
| `done` | `●` | 跑完了 |
| `failed` | `✗` | 跑了但失败（带非零退出码） |

**同帧同步**：帧号由**一个全局钟**算出来，所有在跑行共用同一个字形。各行记各自开始
时刻的话，两行并行工具会各闪各的相位 —— 看着像两个互不相干的东西在抢注意力。

**只重画变了的那几行**：`patches()` 返回 `[(行号, 新文本)]`，调用方照单重画。
整块重刷在慢终端上会闪，块越大闪得越厉害。

**长会话兜底**：行数封顶 + "…还有 k 个工具"。看板是**状态**，不是日志 ——
日志归工具卡片和 `/expand`。

**摘要分档**：单个工具给"工具名 + 目标"（就是原来那句"正在读取 x.py"，
带动词和目标的信息量比一个点大）；多个工具才接管，给"共几个 · 几个完成 · 几个待跑"。

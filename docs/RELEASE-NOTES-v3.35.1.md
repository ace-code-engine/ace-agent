# v3.35.1 —— 演示图不再随采集时机漂移（CI 修复）

## 现象

v3.35.0 推上去之后 CI 红了，红在 `demo/record_demo.py --check` 那一步：

```
demo_blocked.svg 骨架不一致（1 处，最多列 3 处）:
L79: 录制='<text class="r#" ...><tspan fill="#d#dce#">◐ 思考中 #s   </tspan>
            <tspan fill="##d#c" ...'
     现在='<text class="r#" ...><tspan fill="#d#dce#">◐ 思考中 #s   </tspan>
            <tspan fill="<别的色号>" ...'
```

文字一模一样，差的是**颜色**。

## 原因

演示图把两件"采集时机"的事录了进去，而它们不是会话内容：

1. **动到转轮的第几帧** —— 取决于录制那一刻动画跑到哪。
2. **"卡住"渐变的色号** —— `ui/ace_spinner` 的卡住程度是**静默时长**的函数，
   颜色从主题色平滑过渡到告警色。本机录的时候是主题色，CI 上多花了几秒，
   录到的是渐变到一半的告警色。

`--check` 只归一化数字（时间戳会变），色号里的字母保留 → 判定"CLI 输出变了"。
真正的输出漂移反而被这种噪声淹掉 —— 这正是那次误报的代价。

顺带发现一处真 bug：`_SPINNER_GLYPHS` 只登记了推理/回答阶段的首字形，
**工具阶段的脉冲字形（`▁▃▅▇`）和"工具参数流入"四角（`▖▘▝▗`）漏了**，
导致一整段转轮动画不会被折叠成"只留最后一帧"。

## 修法

- 录制时把转轮帧**归一到阶段代表字形**（`◑◒◓→◐`、`◇◆→◈`、`▁▃▇→▅`、`▖▝▗→▘`），
  并**去掉该行的颜色段**：演示图展示的是"哪个阶段"，不是"第几帧、什么色号"。
- 归一表**不含 waiting 那三个点**（`·`/`˙`/`•`）—— `·` 也是正文里常见的项目符号，
  按转轮处理会把正常行的颜色剥掉。
- 补全字形登记：`ui/ace_spinner` 五个阶段的全套字形 + 工具看板的脉冲字形。

## 防复发

`[61]` 里加了两条：

1. **演示脚本必须认得 `ui/ace_spinner` 五个阶段的全套字形与工具看板的脉冲字形** ——
   以后加阶段忘了同步，本机就变红，不用等 CI 上"莫名"失败。
2. 录制路径必须走归一（源码级断言）。

> 这次的 CI 失败原因是从 GitHub 的 `::error::` **注解**里读出来的（注解不需要登录，
> job 日志要 admin）。这也是当初把失败项打成注解的原因 —— 否则只能看到一行
> "demo/record_demo.py --check 失败"。

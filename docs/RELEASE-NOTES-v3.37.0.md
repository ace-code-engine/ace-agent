# v3.37.0 —— "好多用不了"的清算：入口一律走界面 · 键位真有实现

> 用户反馈两个字：**好多用不了**。这一版不猜，直接把"界面宣称能用的东西"逐条做成
> 可断言的事实 —— 而且每个修法都写清**为什么坏**。

## 修了什么（都是能复现的真故障）

### 1. 那些"要问人"的命令会和界面抢 stdin

`/model`、`/provider`、`/sessions`、`/history` 弹的是 prompt_toolkit 选择器；
`/permission`、`/sandbox`、`/net`（裸命令）弹的是统一对话框 —— 它们的开关是
`sys.stdin.isatty()`。**在组件界面里这个判断仍然是 True**，但 stdin 已经归界面所有。

结果：命令一按就花屏/卡死。现在所有"要问人"的地方先过一道：

| 入口 | 界面在的时候 |
| --- | --- |
| `_pick_option`（权限/沙箱/联网） | 走界面的**选择框**（可输入过滤） |
| `_select_index`（模型/提供商/会话/历史） | 同上 |
| `_ask_text`（向导步骤 / 回滚确认 / 持久规则） | 走界面的**文本输入框** |
| `_confirm`（计划审批） | 走界面的**确认框**（默认否） |
| `ask_permission`（授权） | 走**授权模态框**（已有，带 200ms 防误触） |

没有界面时逐条回落终端 —— 契约没变，只是多了一条"界面优先"。

### 2. 和弦、Ctrl+C、Shift+Tab：被 Textual 和输入框吃掉的键

这一批全是"按了没反应"，根因各不相同，都是实测出来的：

- **`Ctrl+X` + `e`（和弦第二段）**：App 级的单个字母键位会被 Textual **从上层键位表里
  剔掉** —— 聚焦的 `Input` 声明"可打印字符归我"；就算绑到 `Input` 身上也没用，
  `Input._on_key` 对可打印字符是**直接插入并 stop()**，压根不查绑定。
  → 现在由 `ChordInput._on_key` 先问一句"是不是在和弦里"：挂起时才拦，平时就是普通字母。
- **`Shift+Tab`**：Screen 自己拿它去**反向轮转焦点**（实测按下去焦点跑到会话区、权限档
  一动不动）。→ 改成**优先级键位**，抢在 Screen 之前。
- **`Ctrl+C`**：输入框把它绑成了"复制"。→ 优先级键位改回**中断**（复制仍可用鼠标选中 +
  `Ctrl+Shift+C`）。
- **`Tab`（补全）**：Screen 的焦点轮转同样抢在前面。→ 优先级键位。
- **`Ctrl+J`（换行）**：之前是绑了个**空动作**（没有 `action_newline`）。→ 真往输入框里
  插 `\n`（引擎本来就吃多行消息，粘贴也是这么进来的）。
- **`Ctrl+O`（展开）**：接到了 `/expandall`（总开关），而不是 `/expand`（展开刚才那条）——
  用户按下去以为没反应。→ 各归各位。
- **`Ctrl+F`**：接到了 `/search`（**联网搜索**），而帮助里写的是"搜会话"。
  → 实现真正的**会话内查找**：输入词、跳到命中、再按一次跳下一处。

### 3. 绑了却没有实现的键

新增守卫断言：**键位表里每一条都必须有对应的 `action_*`**（或者明确属于"输入框/对话框
自己处理"）。绑了不实现 = 按下去没反应 = 用户说的"用不了"。

### 4. 缺依赖时不再沉默

没装 Textual 时以前是**悄悄**回退 REPL，用户只会发现"排队/中断/Shift+Tab/F1 怎么都没有"。
现在会明说一句：

```
（组件界面未启用：没装 textual —— 排队 / 两段式中断 / Shift+Tab 切权限 / F1 帮助
  只在组件界面里。装：python setup_env.py --ensure）
```

管道 / `--json` / `--input` 这些**正常回退**不啰嗦（脚本里刷提示只会碍事）。

## 新增测试段 `[63]`（24 项断言）

- **键位表 ↔ 实现**：每条绑定都有 action；
- **真按键**（无终端测试台）：`Shift+Tab` 转档（进 `full` 要按两次）、`Ctrl+C` 中断、
  `Ctrl+X` 后 `e` 触发和弦且触发后自动撤销挂起、字母照常进输入框、`Ctrl+J` 插换行、
  `Esc` 清输入、`Ctrl+F` 会话内查找并跳下一处；
- **真 CLI**：八个"要问人"的命令在组件界面下逐个跑 —— **一个都不许卡住**，
  并且断言它们**一次都没落到 prompt_toolkit**（把 `run_selector` 换成会抛异常的桩）；
- **三个通用模态**：选择框（输入过滤→回车返回值）、文本输入（Esc = `None`，与空串语义不同）、
  确认框（Esc = 否）。

## 一句实话

真终端里的手感（鼠标、窗口缩放、超长会话滚动、粘贴多行）CI 测不到。这一版把
"能不能用"这一类问题尽量变成了本机可断言的事实，但真机上如果还有键位被终端/输入法吃掉，
那只能靠你在真终端里再报一次 —— 报的时候带上"哪个键 / 期望什么 / 实际什么"就够。

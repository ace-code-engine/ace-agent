# v3.38.0 —— 和 Claude Code 对齐的键位与交互（含逐条核实）

> 做法不是"照抄键位表"，而是：**先把上游的键位与语义核实清楚**（官方文档 + changelog，
> 逐条带来源），再决定 ACE 跟哪些、不跟哪些，并把"不跟"的理由写下来。
> 对照表见 `docs/KEYMAP-CLAUDE-PARITY.md`。

## 先说三条核实结果（它们改了我的计划）

1. **`#` 加记忆这个前缀已经没了** —— 上游 v2.0.70（2025-12-15）移除，改让模型编辑
   `CLAUDE.md`。所以 ACE **不追**这个功能（追一个已经删掉的东西没意义）。
   （上游文档里还留着一个提到 `#` 的主题变量，是陈旧的，这里记一笔以免以后又被它误导。）
2. **`Ctrl+R` 不是"详细模式"** —— 那是 v1.0.113 之前的旧绑定，如今详细视图在 `Ctrl+O`，
   `Ctrl+R` 是**反向搜索历史**。ACE 这边正好一致（`Ctrl+R` = 模糊历史，`Ctrl+O` = 展开）。
3. **`Shift+Tab` 的环不止三档**（default/Manual → acceptEdits → plan → [bypass, auto]），
   且**从 auto 出发第一下回 default**。ACE 的档位由执行层定义（readonly/write/full），
   所以保持自己的环，但把"进 full 要按两次"这条安全设计留下。

## 这一版加了什么

### 行编辑补齐（readline/emacs 那一套，逐条可断言）

| 键 | 行为 | 为什么需要 |
| --- | --- | --- |
| `Ctrl+W` / `Alt+Backspace` | 按**空白**删前一个词 | `src/utils/foo.ts` 一下删干净 |
| `Alt+B` / `Alt+F` | 按**字母数字**走词 | `_ . /` 是分隔符，能一步步走。**与 `Ctrl+W` 的口径故意不同**（readline 就是这样） |
| `Alt+D` | 删到词尾 | |
| `Ctrl+K` / `Ctrl+U` | 删到行尾 / 行首 | 两条都进 **kill ring** |
| `Ctrl+Y` | 粘回刚删掉的 | 上面三条的回收站 |
| `Ctrl+_` / `Ctrl+Shift+-` | **撤销上一次输入编辑** | 不是 `Ctrl+Z`（那是终端挂起键） |

### Esc 的上下文语义（一个键，两件事）

- **有草稿** → 清空，但**存进历史**（`↑` 能召回）——清空不等于丢掉；
- **空输入再按一次** → 打开**回退菜单**：只退对话（`/rewind`）或回退文件到某个快照
  （`/rollback <id>`）。"退什么"必须让用户选：只退对话和回退文件是两种完全不同的后果。

### 队列语义的另一半

- `Ctrl+X Enter` = **排队发送，不打断**当前这一轮；
- `Ctrl+X Ctrl+S` = **立刻发送**：打断当前轮，草稿立刻发出去。
- （`Ctrl+Enter` 很多终端送不出来，所以给的是和弦那条路。）

### 授权对话框：拒绝也能带一句话

`Tab` 打开备注框 —— 拒绝时这句话会**回传给模型**当理由（"不行"从一堵墙变成一次纠偏）；
允许时则作为一句补充说明打出来。

### 其它

- `Ctrl+G` / `Ctrl+X Ctrl+E`：把输入丢进 `$EDITOR`（Windows 退 `notepad`）编辑，存盘读回来；
- `Ctrl+V` / `Alt+V`：粘贴剪贴板图片（**仅 Windows**；非 Windows 或没图时明说，不假装）；
- `?`（空输入）：帮助面板；
- 多行输入三件套：`Ctrl+J` / `Alt+Enter` / `Shift+Enter` + **行尾 `\` 续行**（所有终端可用）；
- **提交时去掉不可见字符**（零宽/双向控制/标签字符）：粘贴里的提示注入最爱藏这里，
  去掉几个就报几个。波斯语/印度语连接符与 emoji 变体选择符**保留**。

## 这一版修掉的"按了没反应"（都是实测出来的）

- **`Ctrl+F` 被输入框抢走**：Textual 的 `Input` 把 `Ctrl+F` 绑成了"删掉右侧一个词"。
  → 改优先级键位。**这条之前一直是坏的**（上一版只测了程序调用，没测真按键）。
- **`Ctrl+W` / `Ctrl+U` / `Ctrl+K` 也归输入框**：功能是有的，但**不填 kill ring**、
  词边界口径也不同。→ 自己在 `_on_key` 里接，顺带把 kill ring 填上。
- **撤销方向反了**：`Input.Changed` 是**事后**通知，照它记撤销点等于把"当前值"再设一遍
  —— 表现就是"撤销没反应"。→ 改成记**变化前**的状态。
- **`Ctrl+X Ctrl+S` 没真的发出去**：只改了状态没启动引擎。→ 补上。

## 验证

- 新增测试段 `[64]`（24 项）：**真按键**驱动 —— 两种词边界、kill ring 往返、`Ctrl+K/U`、
  撤销逐键、`Ctrl+F` 抢回、`?` 帮助、队列两态、Esc 两态、回退菜单、图片有/无、
  不可见字符净化、授权备注回传；
- 三个环境各跑一遍全量：装了 textual+prompt_toolkit、stdin 接 devnull（模拟 CI）、
  无依赖解释器。i18n 三语各 612 键对齐。

## 老实说，没做的

`Ctrl+B` 后台化（ACE 没有这条通路）、检查点的 6 个细分动作、转写分页器的 `less` 键、
emoji 短码/拼写检查/语音、大段粘贴折叠（`[Pasted text #N]`）。理由都写进对照表第五节了 ——
**能说清"为什么不做"，比硬凑十几个键更值**。

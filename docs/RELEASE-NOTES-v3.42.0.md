> 这一版做三件事：

## 一、6 处"承诺了、但没做"（安全与边界）

| 症状 | 实测证据 | 现在 |
|---|---|---|
| `code_execute` 在 `job` 档**静默回落到宿主执行** | 同一个"执行器不可用"状态：`terminal_exec` 报 503，`code_execute` 掉出分支直接 `subprocess.run` | 两者同口径：拿不到边界就 **503** + `go build` 指引 |
| L4 守门是"**第一条失败规则就返回**"，而前两条是 warn 级 | 一段带未注解 `def` 的代码可以让 `no_hardcoded_secrets` / `no_sql_injection` / `v1_ast_check` **一次都不跑**（模型顺手写个 `def` 就能关掉密钥检查） | 跑完全部规则，按 **block > warn** 汇总 |
| **项目级 MCP 没有信任门** | `git clone <陌生仓库> && ace` 会执行它指定的二进制并把整套环境（含 API key）交给它；而 `.ace/hooks.json` 一直要显式信任 | 复用同一道门，默认不加载并**如实说明原因**；子进程剥离 `_HOOK_ENV_DENY` |
| **飞轮把违规原文写进项目内文件** | 最常命中的规则就是 `no_hardcoded_secrets`：刚拦下的密钥被写进 `<项目>/.agent_flywheel/violations.jsonl`，`export_for_sft()` 还当 prompt 导出 | 只留 rule + sha256 + 长度 |
| **`!命令` 与 `/review` 回填绕过整个执行层** | 权限等级、逐次确认、项目外确认、**快照**（`/undo` 回不去）与**审计**全部绕过，而 docstring 写着"走的是同一道执行层闸门" | 新增 `run_tool_direct()`；刻意**不设** `ctx.confirmed`（设真会把 `!rm` 从拒绝变成放行） |
| **`--serve` 的版本字段不严** | `v` 缺省被接受、`v="abc"` 抛裸 `ValueError` 穿出 `serve_forever` —— 一条畸形帧带走服务进程 | `v` 必填且必须是整数，坏值一律 `ServeError` |

复核：`python test_all.py --only 70`（`D1`–`D10` 那批断言就是这些的回归）。

## 二、三类"静默丢数据"

| 症状 | 实测 | 现在 |
|---|---|---|
| **记忆：一条坏 entry 带走全部** | 文件 3 条（2 好 + 1 条缺字段）→ 加载后内存 **0 条** → 下一次 `add()` 把用户全部跨会话记忆抹成 1 条，零提示 | 逐条容错；整文件读不出来时把原文**隔离**成 `<name>.corrupt-<ts>`（绝不就地清空），`stats()` 如实上报 |
| **记忆：主会话与子代理互相覆盖** | 两个 `MemoryArchive` 同时活着：磁盘只剩主会话那两条，子代理那条被整批覆盖 | 写回前与磁盘**合并**（按身份去重），只见增加不见减少 |
| **目标：`disarm` 被静默复活** | 启动时 disarm（"重启后不自动续跑"），另一个仍在跑的实例 `start_round()` 把整个目标写回、暂停改成运行 | 变更前重读磁盘；`update`/`resume` 的 CAS 比的是**磁盘当前值** |

另外两处判据错：**任务身份用文本相等判断**（同一句话重发 → 反幻觉闸门被绕过 / 新请求被指纹误熔断，
现在由前端显式给 `task_id`）、**权限三份真相**（`/permission write` 后模型仍看不到写工具，
现在请求时从 `el.permission.level` 现算）；以及两处旧账：反幻觉判据漏检 `改好了 / 弄好了 /
修复了 / 处理完了`（已补齐）、headless 每条请求发两条 system（第一条空串）。

## 三、新增：Rust 元处理内核 `engine/`（只读 · 只算不裁）

- **会话事件流索引**：分类计数、**体积账**、seq 体检、工具成/败、时间线；**Python 侧一个 JSON
  都不解**（原始行直接送过去解析）。
- 它算出的第一件事就有价值：一份 132 KB / 122 事件的真实日志里 **95% 是重复内容**
  （132,350 B → 去重 6,871 B），主因是 `system/snapshot` 每轮重写完整系统提示词（88%）。
  **这个数此前没有任何地方算过。**
- 边界写死在代码里：**不判权限、不看路径、不碰文件系统、不联网**。所以它可以被杀、被替换、
  坏掉只会变慢。零依赖（自实现 MD5 与最小 JSON），`cargo build --offline` 可构建；
  发布产物没有它时自动降级为纯 Python 同口径实现。

复核：

```bash
cd engine && cargo test --offline && ./target/release/ace-engine --selftest
python engine/tools/xcheck.py          # 在真实数据上逐字段对拍（8 项）
```

## 四、新增：运行度量与跨会话成本

- **两样事实以前只活在内存里**：工具耗时（`result.metadata["elapsed"]`）与 token 用量
  （`self._cost`）。而 `ts` 只有秒级粒度（262 份真实日志：平均 11.2 事件却只有 1.8 个不同 ts），
  所以"哪个工具慢""花了多少"从日志里**推不出来**，会话一关就永远丢了。
- 现在 `tool/result` 带 `elapsed_ms`，新增 `model/usage` 事件（每轮**增量** —— 累计值写进
  append-only 日志，重放会翻倍）。`/audit stats` 多一行运行度量；**`/status` 与主页**多一行
  跨会话累计（最近 10 段 + 本次）。成本仍由 `core/ace_cost` 的价目表算 —— 引擎只带 token 事实，
  **不持有价格**；没有价目表时如实显示 `—`。
- 老日志没有这两个字段时**如实显示 0**，不编数字（那是"当时没记"，不是"没算"）。

## 五、写前快照：校验并行化 4.4×，另有一条 12× 的开关

拆开 `snapshot()` 实测：遍历 4 ms、**源哈希 21 ms（1%）**、复制 159 ms、**读回校验副本 2162 ms
（92%）**。而那 92% **不是 CPU** —— 单个 12 MB 大文件 SHA256 有 788 MB/s，贵的是**新写入文件的
首次读取**：顺序 2.84 ms/文件，同一批再读一遍只要 0.06 ms/文件（51× 落差）。

- 默认档：8 线程读回，夹具端到端 **8.7 s → 2.0 s（4.4×）**，判定与顺序版逐字一致。
- 新增 `snapshot_verify`（默认 `create`，与旧行为逐字相同）。配成 `rollback` 把**同一遍**校验挪到
  `/undo` 那一刻：**1958 ms → 162 ms（12×）**。**校验一步都没少** —— 坏快照两档下都
  **不会被静默恢复**（`rollback()` 第一步就是完整性预检）。代价是暴露更晚。
- **默认值定案 `create`，且这 1.8 s 确认降不下来**（登记为 Q-16，已收口）：对刚复制出来的副本
  校验 **24.4 ms/文件**，紧接着对**同一份快照**再验一遍只要 **0.07 ms/文件**（**348×**）——贵的
  是"新写入文件的首次读盘"；哈希本身 347 文件 / 11.7 MB 全热读只要 **34 ms**（便宜约 50×）；
  并发也**已到顶**：1/2/4/8 线程 8646/4850/2646/**1929** ms，而 12 及以上线程反而更慢
  （12 线程 2215 ms）。所以这是个明码标价的取舍，不是待修的慢点：快照每次都建，`create` 就是
  "每次写多花约 1.8 s 换坏快照早暴露"。以上数字均在本机 Windows 测得。

## 六、升级注意

| 变化 | 影响 |
|---|---|
| `!命令` / `/review` 回填受权限档约束 | 只读档下会被拒并提示 `/permission write` |
| 飞轮不再落违规原文 | 取样需按 sha256 从会话日志取回并自行脱敏 |
| `disarm` 不再被别的实例写回 | 恢复需要显式 `resume` |
| `/status`、主页、`/audit stats` 各多一行 | 老日志的耗时/token 显示 0 |
| 演示图**已重录**（四张） | `/status` 多一行 + 版本号 → `demo.svg` / `demo_blocked.svg` / `demo_diff.svg` / `demo_landing.svg` 全部重录；顺带修好了图里那个**缺角的框**（见下） |
| 冻结版（`ace.exe`）**不带 Rust 引擎** | 自动走纯 Python 同口径实现（字段集对齐、输出一致，只是部分命令略慢）。**这是决定不是遗漏**：实测引擎在热路径上没有收益，进包却要给 CI 加一套按平台编的 Rust 工具链并长期维持两份实现逐字节一致。理由、实测与"要改回去怎么做"见 `docs/PACKAGING-EXE.md` |

**关于演示图**：本版改了 `/status` 输出（多一行跨会话累计）并升了版本号，四张演示图都已重录，
`python demo/record_demo.py --check` **四张全绿**。重录过程里还查出并修掉了一个一直存在的缺陷：

- 录制脚本把临时目录的绝对路径**直接换成了一个 `…`**，而面板的补白是**按真实路径算好之后**才折叠的 ——
  于是那一行比同框其它行短掉一大截。**已提交的 `demo.svg` 里「当前会话」那个框本来就是缺一角的**
  （实测：其余行 96 列，`目录` 那行只有 28 列）。顺带，路径长度也被写进了发布资产
  （本机 work 路径 50 列、CI 69 列），这就是 `--check` 在 CI 上必然对不上的**真正原因** ——
  此前归因为"列宽渲染不同源、必须去同源机器重录"，那个归因是错的。
- 现在折叠分两种口径（框内行保宽、自由行折成一列），录制结果**与在哪台机器录无关**：
  实测把临时目录加长 17 列，四套剧本录出的骨架逐字节一致；`test_all [61]` 有断言钉住。
  **重录不再需要找"与 CI 同源"的机器**（`docs/DEVELOPMENT.md` 已改正）。

## 七、测试

- 新增 **56 条回归断言**：`D1–D10`（本版全部缺陷）、`E1–E5`（事件索引与跨语言 kind 名单）、
  `F1–F9`（快照校验与校验时机）、`G1–G5`（状态文件）、`H1–H4`（度量）、`I1–I5`（跨会话与成本）、
  `J1–J2`（主页），另有 **4 条演示录制不变量**（框内保宽 / 自由行折一列 / 先剥 ANSI 再判边框 /
  录制真的走 `_fold_path`）。
- 端到端套件、引擎单测/自检、真实数据对拍各自独立跑；**全量断言随平台浮动，
  以 `python test_all.py` 的实际输出为准**（本机 2310 / 2310 通过，跳过 3 项能力探测）。
- **CI 新增 `engine` 作业**：此前 CI 从不编译引擎 —— 那句 `compileall` 只语法检查了
  `engine/tools/xcheck.py`，于是引擎的 20 条单测、自检，以及 `test_all` 里"引擎路径 ==
  纯 Python 降级路径"那批断言，在 CI 上**都在拿降级路径和它自己比**（二进制不在，两边都是
  Python，恒等成立、必过）。现在 CI 会构建（`--offline`，顺便证明零 crate 依赖）、跑单测与自检、
  然后**先断言引擎真的被发现**、再带着引擎跑 `test_all.py --only 70`（连带依赖段 65 段 / 2308 条）。

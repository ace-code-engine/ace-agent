# v3.43.0 —— 信任锚移出工作区 · 台账链式签名 · 两条"只测量"的判据前置

> 这一版没有新功能给你用，只有三件事：**把一道能被伪造的安全网修成修不了的**、
> **把一份能被静默重写的审计记录修成改得动的看得见**、**把两条要改判据的东西先量出来**。
> 立项与前置门：`docs/design/RGTC-LANDING.md`（RG-01 ~ RG-05）。

## 一、RG-01：签名密钥不再躺在被保护对象的地盘里（缺陷先复现过）

**缺陷**：密钥住在 `<项目>/.guardian/signing_key`，而 `.guardian` 就在项目目录里。拿到项目目录
读写权限的一方可以：读出密钥 → 改快照副本 → 修 `meta.json` 里的摘要 → 用同一把密钥重算 HMAC。
实测这样改完 `verify_snapshot()` **返回 True** —— "写前快照"这道安全网可以被伪造。

**修法**：

- 密钥移到**工作区之外**的锚目录（Windows `%LOCALAPPDATA%\ace-agent\state\<项目哈希>\`，
  POSIX 用 XDG state）；根目录可用 `anchor_dir` 参数或 `ACE_ANCHOR_DIR` 换位置。
- 老项目**迁移时把项目内那份删掉**（只拷不删等于没搬）；删不掉会告警。
- **fail-close 两处**：锚不可用时 `snapshot()` 直接拒绝（走既有的"快照不可用 → 503"），
  不再生成未签名快照；带签名却拿不到密钥的快照**拒绝验证**，不再"跳过签名只比摘要"。

**实测前后**：修复前"改内容+修摘要+重签" → `verify=True`；修复后 → `verify=False`。

## 二、RG-02：会话台账链式签名

**缺陷**：append-only 只保证"只追加"。实测把一条 `permission/decision` 从 `deny` 改成 `allow`、
或往尾部追加一条伪造事件，`seq_contiguous()` 都返回 `True`，日志里**没有任何字段**能说明它被动过。

**修法**：每条事件带 `mac = HMAC(台账密钥, 上一条的 mac ‖ 该条正文)`；`/audit stats` 增加整链
校验行，**三态分开报** —— `ok` / `broken` / `unverifiable`（老日志或拿不到密钥）。

**一处刻意的偏离**：台账密钥不可用时**不** fail-close，而是照写 + 告警 + 报 `unverifiable`。
台账是**记录**不是**闸门**：因为写不了签名就让整轮对话挂掉，换不来任何安全收益
（攻击者本来就能删掉整份日志）。快照是闸门，所以那条必须 fail-close —— 两条路故意不同。

**开销**：单条 MAC 计算 **6.5 µs**；`append` 整条路径 11.4 ms/条，其中绝大部分是**既有的** `os.fsync`。

## 三、RG-03 / RG-04：只测量，不改裁决

**RG-03 来源归属** —— 先复现：同一句 `file_delete(notes.txt)`，配"用户明确要求删它"、
"用户只让看 README（删除指令来自读到的外部内容）"、"用户完全没提过这个文件"，**三条裁决
一模一样，全部 SUCCESS，文件全被删，零弹窗**。执行层根本回答不了"是谁让做的"。
本版只做测量：记下"目标有没有被用户提过"，`/audit stats` 打一行分布，**不改裁决**。

**RG-04 可逆性分类器** —— 把"这条命令危险吗"（名单补不全）换成"**被写的对象能不能重建**"。
按事实分五级：`GIT` / `SNAPSHOT` / `REGENERABLE`（白名单里的依赖与构建产物）/
`NEVER`（凭据 / agent 自身状态 / 版本库自身 / 设备 / 工作区外）/ `UNKNOWN`（说不清）。
**实测真实工作区 7851 个文件**：可重建 85.7%、说不清 8.2%、不可重建 6.1%。
那 8.2% 就是"若开判据"的代价 —— 约 8.2% 的目标上的写会从"直接放行"变成"问人"。

**两条口径是被测试当场抓住才写对的**：① **"被 gitignore" ≠ "可再生"**（私有笔记、`secrets/`
同样被忽略，删了不可重建 → 一律判 `UNKNOWN`）；② **`sensitive_target` 与 `is_credential_file`
是两个问题**（前者答"工具能不能碰"，后者才是"快照有没有备份它"；混用会把 `.env` 判成可逆）。

## 四、RG-05a：授权令（一次任务一张令，默认不配 = 行为与以前完全相同）

审批粒度原来是**对象**（H-09），弹窗随危险步数线性增长。授权令换成**一次任务一张**：
`(intents, roots, recoveryFloor, irreversibleQuota, ttl)` + 签名（密钥从**锚**派生）。

```bash
python -m cli.ace_mandate issue --intents file_write --roots . \
    --floor snapshot --quota 1 --allow-irreversible terminal_exec --ttl 3600
```

贴进配置的 `"mandate"` 键即生效。**能覆盖的只有两处"问人"**：项目外已存在对象的确认、
`edit_file` / `terminal_exec` 的逐次确认（后者必须点名并消耗额度 —— 它们的痕迹不可枚举）。
**覆盖不了**：硬拒绝（持久规则 / 未注册 MCP / 敏感目标）、外发确认（那是"目的地"轴）、权限等级
（与 `/rules` 的 allow 同一先例）。令坏了（改过 / 过期 / 签名不符）**不说放行**，回落成照旧确认
并告警一次。

**收益实测**（`e2e/rg_probes.py rg05`）：同样 5 次项目外写 —— 不配令 **5 次**逐次确认 →
配令（roots 覆盖 + 额度 5）**0 次**；配额只给 2 时仍有 **3 次**确认（额度是真边界）。

## 五、升级注意

| 变化 | 影响 |
|---|---|
| 签名密钥移出项目目录 | 老项目第一次启动会自动迁移（**搬**：写锚 → 读回校验 → 删旧）；旧快照仍验得过 |
| 锚不可写 → 写操作被拒 | 这是 fail-close，不是 bug；`python -m cli.ace_doctor` 会告诉你锚在哪、什么状态 |
| 会话日志带 `mac` 字段 | 老日志被如实判为 `unverifiable`（不冒充 ok，也不冤枉成 broken） |
| `/audit stats` 多两行 | 台账整链校验 + 两条测量（来源归属、可逆性），均注明"未参与裁决" |
| **新增配置键 `mandate`** | **不配就什么都没有**（行为与以前逐字相同）；配了才收拢逐次确认 |
| 本版**不改任何默认裁决行为** | 两条判据只测量；授权令默认关闭；`/audit stats` 的那两行是"若开判据会怎样"的预测 |

## 六、已知未验证（延续）

- RG-03 / RG-04 的**判据翻判**未做：前者需要模型侧引用（协议改动），后者需要 G2 清单逐条看过。
  两者都要真会话数据，本版只把数攒出来。
- **影子平台（原型的能力回归主力）实测后决定不做**：真实工作区量到"复制 + 前后各一遍冷指纹"
  单次 **11.6 ~ 21.8 s**（门槛 300 ms，超 39 ~ 73 倍；区间来自两次独立实测，冷读那一段波动大），
  其中大头是**刚写出来的副本首次被读**（约 10 s）；且本机工作区在 **NTFS** 上，Windows 只有
  ReFS 才有块克隆，没有廉价写时复制这条替代路。数字与理由见 `docs/design/RGTC-LANDING.md` 的
  RG-05b，随时可用 `python e2e/rg_probes.py rg05b` 重跑。
- 锚在**不可写的状态目录**上时写操作会被拒（本机受限环境实测就是这样，行为正确但陡峭）：
  这类环境用 `ACE_ANCHOR_DIR` 指到可写位置。
- 本机跑的是 Windows；POSIX 下 `0600` 与 XDG 路径有断言覆盖，但**没有实机冒烟**。

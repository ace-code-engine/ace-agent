# 为什么是 HooH —— 名称 · 对比 · 设计取向

> 从 README 迁出（首页只留一句话钩子，全文在这里）。
> 改名过程、被否掉的候选与知识产权口径见 [`NAMING.md`](NAMING.md)。

## 名称：`互`

**HooH = 互。** 这个字描述的是系统的**形状**，不是一个好听的代号：

- **模型提出 ⇄ 代码裁决。** 一次工具调用是一次问答：模型说"我要做这个"，执行层回答
  "行 / 不行 / 你得先问人"。有来有回，才叫互。
- **先写快照 ⇄ 才谈得上 undo。** 回滚能力不是后加的补丁，它跟写入是同一件事的两面。
- **HMAC 是链式的。** 每条审计记录挂着前一条的摘要，改动一条就断链 —— 链节互相咬住，也是互。

中文写「互」，英文写 `HooH`，命令行一律 `hooh`（4 字母、全小写）。
**`互` 只做展示与叙事，不做命令名、目录名或环境变量** —— 那些一律 ASCII。

> 与《崩坏：星穹铁道》的"均衡"星神同名，是致意而非取材：仓库内**不含任何米哈游素材**，
> 图标是按本项目自身视觉语言画的「互」字几何构图。权利人有异议提 issue 即改。

改名前的旧名是 **ACE · AI Code Engine**。为什么要换：`ACE` 被至少五个互不相关的项目、
框架与认证占用（ACE 编辑器 / ACE 框架 / ACE-Step / Adobe Certified Expert /
American Council on Exercise），首页第一屏得靠一段免责声明才能说清自己是谁 ——
那本身就是同质化的量化形态。**换名的收益不是好听，是那一整段免责声明可以删掉。**

## 安全不该住在提示词里

大多数 Agent 把安全交给提示词："请不要删除文件"。HooH 不这么做。

模型的**每一次工具调用**都要穿过一个独立的执行层，由它做权限裁决、危险行为检测、写入前物理快照。提示词失效时 —— 被越狱、被注入的网页、被篡改的工具输出 —— 那一层仍然在。

> 如果你的需求只是**聊天式 AI 编程**（对话里生成代码、不改文件、不执行命令），HooH 未必必要。如果你的 Agent 要**真实地改文件、执行代码、访问网络**，并且你不希望这件事依赖模型的自觉 —— 那 HooH 才是目标场景。

## HooH 与「提示词护栏」型 Agent 的差别

| | 典型的提示词护栏 Agent | HooH |
|---|---|---|
| 「我有没有权限」在哪裁决 | 提示词里 | 执行层里，**每次调用**都过（`execution_layer.py`） |
| 提示词被注入 / 被越狱之后 | 看模型怎么决定 | 权限闸门、路径边界、敏感目标拦截照样生效 |
| 执行一条 shell 命令 | 模型直接跑 | `terminal_exec` **每次都问人** —— 它的黑名单可被绕过，所以「人」才是那道边界 |
| 撤销一次坏改动 | 指望 git | 每次写入前都有物理快照，`/undo` 一键回滚 |
| 数据离开这台机器 | 模型调 API 就走 | 外发闸门：目的地未知 ⇒ 确认；`egress_allowlist` ⇒ 一次性授权 |
| 离线、没有 API Key | 通常需要密钥 | `python ai_code.py --mock` 离线跑完整闭环 |
| 隔离 | 提示词级 | 三档：`off`（进程内策略）/ `job`（Windows Job Object）/ `docker`（一次性容器）—— 拿不到边界就返回 **503，绝不静默回退** |

## 设计取向

- **安全属于执行层，不属于提示词。** 权限裁决、危险命令拦截、写入前快照都在 `execution_layer.py` 里，与模型无关。换模型、模型被越狱、提示词被覆盖，这层都还在。
- **默认只读。** 起步权限是 `readonly`，写工具会被 403 拦下。提权是**人的动作**（`/permission write`），不是模型能自己发的。
- **边界要说清能挡什么、挡不住什么。** 全仓没有一句"完全安全"的宣称 —— 见 [安全边界 FAQ](security/SECURITY-FAQ.md)。
- **改名只动展示层。** `ace.cmd` / `ace.exe` / `ACE_*` 环境变量 / `.ace*` 状态目录 /
  MCP 的 `serverName` 全部保留 —— 那些是已装用户的兼容面，改了会丢会话、
  断掉签名密钥锚、让 host 配置失效。新入口 `hooh.cmd` 与旧入口并存。

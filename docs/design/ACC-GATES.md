## 1. 目标与非目标

### 目标

1. **ACE 的每个数字都能被独立复核**：先让**厂商的真值**进账本，再谈门槛。
2. **四道门槛各自可执行**：ACC-01 有度量与判据；ACC-02/03 有**模板 + 断言**（不是文风要求）；
   ACC-04 有**能被 CI 跑的清单**。
3. **不产出功能也产出保护**：任何 WP 的"完成"声明都要过这四道。

### 非目标（明确不做）

- **不做账单系统**：只回答"自报数与实测数是否一致"，不做计费、不对账厂商发票。
- **不改 `estimate_tokens` 的用途**：它作为**上下文预算**的估法是刻意的（`ace_context.py:47`：低估不可接受）。
  本卡**不动它** —— 要改的是"**把它当成事实往外报**"这件事。
- **不新增价格表口径**：价格仍是 `core/ace_cost` 的单一来源
  （`ace_engine.py:497` 已定"引擎只带事实，不持有价格"）。
- **不为 ACC 新增发布通道**：门槛是**加在既有 CI 与既有完成流程上**的，不新开 job（与 §2.7 硬契约 3 同一条纪律）。

## 7. 实施记录：A0（2026-09-27）

> 目标（本卡 §3 的 A0）：**让厂商的真值进账本**。第一步且最便宜，且**完全不碰** `estimate_tokens`。

### 7.1 改了什么

| 文件 | 改动 |
|---|---|
| `core/ace_client.py` | 新增三个纯函数 `_openai_usage` / `_anthropic_usage` / `_note_usage`；**`on_usage` 回调贯穿六个入口**：`chat_complete` · `stream_openai` · `post_anthropic` · `stream_anthropic` · `chat_stream` · `chat_once`。**不改返回元数**（与 `on_delta` / `on_retry` 同形），既有调用点一行都不用改 |
| `ai_code.py` | `ModelClient._last_provider_usage`（每轮 `stream_generate` 开始时清空）+ `_note_provider_usage`；把记账那段抽成 **`_record_turn_usage`**（这样才能被单独驱动 —— A0 的第 ⑥ 条就是靠它） |
| `cli/ace_sessionlog.py` | `record_usage(..., measured_in=None, measured_out=None)` → 事件**正交新增** `measured_in_tokens` / `measured_out_tokens`，**拿不到就不写这两个键** |

**逐一处理了四种响应形状**（这是 A0 的真正工作量，不是"读一个字段"）：

| 路径 | 用量在哪 |
|---|---|
| OpenAI 非流式 | 顶层 `usage.prompt_tokens` / `completion_tokens` |
| OpenAI 流式 | **收尾分片**里，而那个分片的 `choices` 是**空数组** ⇒ 必须在"取 choices"**之前**读，否则会跟着 `delta` 一起被当成"没内容"跳过 |
| Anthropic 非流式 | 顶层 `usage.input_tokens` / `output_tokens` |
| Anthropic 流式 | **分两处**：`message_start.message.usage.input_tokens` 与 `message_delta.usage.output_tokens` ⇒ 各收各的，两半到齐才算 |

**两条口径决定（都是"宁可说不知道"）**：① 字段缺一个就返回 `None`，**不拿 0 冒充"没用量"**（与 `ace_cost` 的"价格未知"同一条）；② `_note_usage` 里回调抛异常被吞掉 —— 记账失败不该把一次成功的模型调用变成失败（与 `on_delta`/`on_retry` 同纪律）。

| ③ | Anthropic 非流式 | ✅ |
| ④ | Anthropic **流式**：两半合成一个数 | ✅ |

| ⑦ | 拿不到实测时**不写那两个键**（也不拿估算顶替） | ✅ |

### 7.3 两处**刻意不做**的事（各有一条可验证的理由）

1. **不主动加 `stream_options: {"include_usage": true}`。** 那是**请求参数**，端点不认就 400 —— 而 A0 的立场是"只读不讨"：读得到就读，读不到留空（`estimated` 那半照旧）。要"流式也一定有实测"，前提是先有一个"这个端点认不认这个参数"的判据，单列。

# WP-9 · 沙箱后端（接腾讯云 CubeSandbox）—— 立项卡

> **SEC 编号：`SEC-020`**（`docs/security/SECURITY-AUDIT.md` 的 `SEC-001~019` 已用满，本条为首次登记）。
> **C6 前置**：本卡即 C6 要求的"单独立卡"。上级：`docs/ROADMAP.md` §4 WP-9 · §2.6 授权模型 · §7.1 **C6**。
> **风险：全路线图最高** —— 这是**唯一新增远程执行通道**的一项（`ROADMAP` §7.2 原话）。

## 一、要做什么

`ROADMAP` §4 WP-9：把 H-30 的"**没有 OS 边界就 503 拒绝**"升级为"**有边界就跑**"。三层：

| 层 | 边界 | 何时用 | 状态 |
|---|---|---|---|
| **Tier 0** | 无边界 → **拒绝**（现状） | 默认 | ✅ 已有（H-30） |
| **Tier 1** | 本地 Go `executor/` + Job Object | 本地可信机器 | ✅ 已有 |
| **Tier 2** | **CubeSandbox MicroVM**（KVM/RustVMM，数十 ms 启动） | 不可信代码 / 远程 / 高并发 | ❌ **本卡** |

## 二、**S-1 的边界（这条不明说就会撞穿权限模型）**

> **可以把「执行边界」外包给沙箱；不可以把「决定权」外包出去。**

沙箱是 Tier 0 拒绝掉的那个缺口的**补集**，不是权限层的替代品。`execution_layer` 仍然是唯一裁决处；
CubeSandbox 不可达时**降级方向必须朝"更严"** —— 降级到 **Tier 0 拒绝**，**绝不**降级到本地无边界执行。

## 三、验收（四条，全部来自 CubeSandbox 与参照系踩过的坑）

1. **凭据绝不进沙箱环境** —— `-e` / SDK `envVars` **服务端可见**（Codewhale 的 Daytona 注记踩过）。
2. **模板/快照固化前必须扫凭据** —— 复用 `core/sensitive.py`（SEC-014 的同一份清单，不另立）。
3. **出网默认拒绝，域名显式放行** —— 与 ACE `egress_allowlist` **同一口径、同一清单**（WP-8 已落地，见 G-12）。
4. **故障降级朝"更严"** —— 不可达 → Tier 0 拒绝（可断言：构造一个"沙箱不可达"的用例，必须拒绝而不是本地跑）。

**ACC 门槛（C6 要求先过）**：上报物料须齐**五要素 + 六要素**、五种偷换各一条被拒（`core/ace_contracts.py` 的唯一判定处）。
本项的缺陷形态可以预见：**"沙箱跑起来了"与"沙箱真的隔离了"是两件事** —— 六要素里的 `Production producer` 必须指向**隔离失效的那个代码位置**，不是"KVM 应该能隔离"。

## 四、不做（写进卡，防范围漂移）

- **不自研**容器 / micro-VM（`ROADMAP` NG-01）：接 CubeSandbox，不是重写它。
- 不动 `execution_layer` 的权限架构（S-1）；不新增第二条裁决路径。
- 不做 CubeTemplateCenter 的模板市场（那是 CubeSandbox 的产品面）。

## 五、边界（本卡只立规，不含实现）

实现开工时另出**实施记录**进 `docs/design/THREE-LAYERS.md` §9 同级的卡；本卡只定"三层结构 + S-1 边界 + 四条验收"。

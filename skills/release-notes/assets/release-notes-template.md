# 发布说明模板（release-notes）

> 破坏性变更永远在最上面。没有的那一节就**整节删掉**，不要留空标题。

## vX.Y.Z（YYYY-MM-DD）

一句话：<这次版本对用户意味着什么，30 字以内>

### ⚠ 破坏性变更

- **<变了什么>** —— 影响：<谁会受影响>；升级要做什么：<具体动作>

### 新功能

- <用户能做到的新事>（`<命令/参数/工具>`）

### 改进

- <同一件事变得更快/更稳/更清楚>（<可核对的口径，如"冷启动 1.2s → 0.4s">）

### 修复

- <症状>（<触发条件>）

### 内部

- <依赖升级 / CI / 重构 / 文档>（用户无需动作）

---

### 升级提示（非破坏性但值得说）

- <配置键默认值变化、行为微调、需要注意的日志变化>

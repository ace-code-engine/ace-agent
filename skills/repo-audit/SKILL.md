# 仓库体检（repo-audit）

一个**只读**的体检流程：先取证，再下结论。目标不是"写出漂亮的报告"，而是让用户拿到的每一条
结论都能被独立复核 —— 说不清出处的结论，宁可不说。

## 步骤

1. **先读判据**：本技能自带的 `references/checklist.md` 是这次的检查清单。**不要自己另发明
   一套** —— 清单之外的发现可以另开一节，但清单每一项都要有结论（含"没查/查不到"）。
2. **取证**（只读工具）：
   - 用 `glob` / `file_read` 看项目骨架：构建文件、入口、测试目录、CI 配置；
   - 用 `grep` 找信号：`TODO|FIXME|HACK`、`except: pass`、硬编码密钥形状（`sk-`/`AKIA`）、
     `eval(`、`shell=True`、`verify=False`；
   - 用 `terminal_exec` 跑**仓库里已经存在的**命令（例如 `git log --oneline -20`、
     已有的测试命令）。**不装依赖、不改配置、不跑发布脚本。**
3. **交叉验证**：一条怀疑至少要有两处证据（代码 + 可复现的命令输出，或两处独立代码位置）。
   只有一处时，写进"待确认"，不要写进"问题"。
4. **写报告**：按 `assets/report-template.md` 的结构；每条结论都带 `路径:行号` 与原文片段。
   需要落盘时写到 `audit-report.md`（这是本技能唯一允许的写操作）。

## 硬规则

- **只读**：不改被审计仓库里的任何文件；除了最后那份报告，不创建新文件。
- **不装依赖、不联网取包**：缺依赖就如实说"没跑测试，因为 X 缺失"。
- **结论与证据同屏**：报告里不出现"大概/应该是"这类结论性措辞（怀疑放"待确认"一节）。
- **发现密钥一律打码**：只报位置与形状（`path:12` + `sk-…`），绝不把完整值抄进报告。

## 产物

- `audit-report.md`（按模板；顶栏写清审计的 commit、时间、范围）

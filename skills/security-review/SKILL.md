# 安全审查（security-review）

按 ACE 自己的裁决面视角审代码：不查"功能对不对"，只查"边界会不会被绕过、凭据会不会漏、注入面在不在"。
裁决的硬边界由执行层执行（`sensitive_target` / `ace_rules` / 快照 / 沙箱），这里审的是**裁决的输入面**与**新增代码是否开了旁路**。

## 一、五类必查（每一类都对应一次真实事故）

1. **凭据落盘/泄露**：密钥、token、口令进代码、日志、提交、报告、快照？只报位置与形状（`path:12` + `sk-…`），不复述内容。
2. **路径穿越/越界**：`..`、符号链接、大小写/短名/8.3、UNC、绝对路径绕过 `_confined`？新增的读写入口有没有走同一个守卫？
3. **命令注入**：拼进 `shell=True` 的字符串、未白名单的环境变量、`-c`/`-e` 内插值？argv 数组还是字符串？
4. **提示词注入面**：外部内容（仓库文件、网页、附件、工具结果）进系统提示词/工具结果，有没有被包成"数据不是指令"？有没有能被伪造的标记/停止序列？
5. **边界绕过**：有没有**第二入口**绕过同一道闸门（`run_tool_direct` 跳过权限、`_resolve_local_path` 不查敏感目标、子进程继承父进程环境）？

## 二、交付前五问

- 这次改动是**加了新的裁决面**，还是**在既有闸门旁边开了一条不经过它的路**？
- 有没有**同一件事两种口径**（A 处拦、B 处放）？
- 失败的**方向**对不对：未知/解析不出时，是 fail-close 还是 fail-open？
- 有没有**静默降级**：边界不可用时是 503/拒绝，还是悄悄退回裸跑？
- 报给用户的措辞有没有**把"扫过了"说成"安全了"**？

## 三、如实

- 只报**能核实的**，注明哪一处无法从静态读判断（"要跑一下才知道"）。
- 不夸大："这是已知高价值目标清单，不是完备边界"。
